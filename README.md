# 墨页 · 私人图书馆

“墨页”是一款使用 Rust、GPUI 与 WebView2 开发的 Windows 本地图书库、阅读器与
编辑器。它把不同来源的图书和文档转换为应用自有的统一内容模型，同时永久保留
每本导入图书字节一致的原文件。

## 功能

- 图书库
  - 导入 EPUB、PDF、DOC/DOCX、PPTX、XLSX，以及未加密的
    MOBI/AZW/AZW3；导入时识别实际文件结构并执行大小与资源上限检查
  - 按内容去重、层级分组，并可同时打开多本图书
  - 输入图书名称后新建一本默认包含 Markdown 章节的可编辑图书；取消或名称为空时不会创建
- 阅读与预览
  - 阅读 EPUB 与规范化后的 Office/Kindle 内容，支持层级目录、上下章导航和进度恢复
  - 使用仓库内置的 PDF.js 在应用内逐页显示 PDF，不加载远程脚本或资源
  - EPUB/PDF 阅读器和编辑器的左侧导航、中央正文、右侧 AI 为可调三栏布局；拖动
    两条分隔线即可分别调整左右栏宽度，窄窗口下 AI 栏仍会自动收起
  - 可按书显式启用 Microsoft Office 增强预览：Word/Excel 通过只读临时 PDF、
    PowerPoint 通过逐页图片生成经校验的本地页面；结果按当前 revision 持久化，
    Office 未安装、失败、取消或用户禁用时仍可使用结构化预览。Word/Excel 重分页后
    这些整本 PDF 页面即使页数恰好等于章节或工作表数，也不能证明精确对应，因此不会
    绑定任何章节，只用于预览，不进入视觉理解、搜索或 AI 引用
- 编辑与导出
  - 编辑元数据、封面、内容单元类型、Markdown/HTML 正文和层级目录
  - 新增、删除、重排内容单元及目录嵌套；插入、替换或删除图片、音频、视频，并编辑
    可进入全文检索的媒体标题和说明
  - 提供源码、预览和本地打包的 ProseMirror 富文本编辑模式
  - 从统一内容模型稳定导出 EPUB 或 PDF；导入的图书还可导出字节一致的原文件
- 搜索与 AI 问答
  - 图书库可按当前分组及其子分组进行关键词、语义和混合搜索；各阅读/编辑窗口另有
    当前文档的即时关键词定位
  - 混合搜索融合全文与向量结果；模型或向量索引不可用时仍可使用全文搜索
  - 图书库、阅读器和编辑器均提供可折叠 AI 侧栏；可新建多个会话，并在当前窗口类型和
    当前图书对应的历史会话之间切换。新会话在发送第一条消息后持久保存，空会话不会
    占用历史列表
  - 历史会话可逐项删除，确认后会不可恢复地删除其中的问题、回答和引用；删除当前会话
    （包括仅剩最后一个时）会回到空白新会话，删除其它会话不影响当前会话，正被其它
    窗口使用的会话不能删除
  - 用户问题和 AI 回答都可选中文字，也可用消息旁的复制按钮复制完整原文；长消息使用
    稳定的气泡宽度，不会因首条消息的内容长度提前窄幅换行
  - 回答会随模型输出逐步显示；工具调用、取消或来源校验失败时会撤回尚未确认的临时正文
  - AI 侧栏持续标明当前端点是本机还是远程主机，避免把远程内容发送状态隐藏在设置中
  - AI Agent 只能在窗口授权的图书范围内搜索正文、读取片段和获取目录
  - Reader、PDF Reader 和 Editor 的非空当前高亮默认加入本次问题，也可在右栏取消；
    清空高亮不会改为引用整章，额外章节或页面仍需在右栏显式多选
  - “可选引用”列表最多显示三行，更多候选可在列表内滚动，避免挤占聊天记录空间
  - 没有选区时不会把内部空快照数组发送给模型；取消或关闭窗口从冻结开始即可生效，
    在冻结完成前取消不会继续创建会话、保存问题或调用模型
  - 回答中的来源必须来自本次问题经校验的搜索结果或冻结选区；有来源时会严格校验，
    模型自行拼造、越权或失效的引用都会被拒绝
  - 若所选图书中没有可验证来源，大模型仍可基于自身通用能力回答，但答案开头会明确
    标为“非知识库回答”，避免与图书内容混淆
  - 页面视觉理解会把 OCR/说明保存为带页面区域的可搜索片段；对话来源同时记录文档与
    内容单元版本；点击正文来源会定位唯一匹配的文字范围，正文变化、范围缺失或匹配
    有歧义时会明确报错，不会悄悄跳到章节开头或其它页面。未保存选区在恢复历史对话
    时若无法由当前正文精确证明，也会明确标记为已失效
  - 默认通过 OpenAI-compatible 接口连接本机 Ollama，也可显式配置其它兼容端点
- 本地与安全
  - 正文、目录、索引、阅读进度和会话保存在 SQLite；原件、封面、媒体和派生页面
    使用 BLAKE3 内容寻址对象存储在本地文件系统
  - 书内脚本、外部网络资源、外部导航、新窗口和下载默认禁用；媒体读取校验图书归属
    并按播放所需范围从对象存储读取
  - 远程 AI 端点不会自动启用，发送内容前需要用户确认；API key 存入 Windows
    Credential Manager，不写入 SQLite
  - 图书库可查看视觉渲染、视觉理解和 embedding 后台任务，并暂停、恢复、重试或取消；
    视觉渲染恢复时复用已持久页面，完整的新页面集准备好之前继续保留旧预览。每个图书
    的当前来源只保留一个有效视觉理解任务；AI 配置未变化时不会重复投递，视觉模型变化
    时会替换旧任务。规范化端点和 embedding 模型都未变化时，修改聊天模型、视觉模型、
    超时或 API key 不会重置已完成的向量任务；embedding 模型或端点变化时只投递一次
    新执行，并在切换时清理旧向量、拒绝旧端点迟到的结果。启动发现遗留重复任务时会
    清除来源不明的旧视觉说明并由唯一任务重建；AI
    配置与全部图书的索引任务会一起提交，失败时保留原配置

## 运行

环境要求：

- Windows 10/11
- Rust stable、`x86_64-pc-windows-msvc` 与 MSVC C++ Build Tools
- Microsoft Edge WebView2 Runtime
- 可选：本地 Ollama，或其它 OpenAI-compatible 服务
- 可选：Microsoft Word、Excel、PowerPoint，仅用于用户显式启用的增强预览

墨页会在启动时检测 WebView2 Runtime。若系统中没有可用版本，应用会询问是否打开
[微软官方 WebView2 Runtime 安装页面](https://developer.microsoft.com/microsoft-edge/webview2/consumer/)。
安装 Evergreen Runtime 后，重新启动墨页即可。

```powershell
cargo run --release --locked --bin moye-epub-editor
```

编辑器和 PDF.js 构建产物已经随仓库固定，普通 Cargo 构建不需要 Node.js。

## AI Provider

默认端点是 `http://127.0.0.1:11434/v1`；聊天和视觉模型默认使用
`qwen3.5:0.8b`，embedding 模型默认使用 `qwen3-embedding:0.6b`。在“AI 设置”中可分别
修改三个模型，并设置 1–600 秒的单次 HTTP 请求总超时（默认 120 秒）；墨页只检测
连接、读取模型并提供缺失模型的 `ollama pull` 提示，不会启动、停止 Ollama，也不会
从本机端点静默切换到云端。AI 设置在应用内只打开一个窗口；重复点击会激活并恢复
已经打开的窗口，不会丢失其中尚未保存的输入。

非回环端点会显示远程发送提示并要求确认；该确认只对当时的准确端点生效，修改 URL
后必须重新确认。非 HTTPS 的远程端点还需要额外显式允许。
语义搜索和视觉理解依赖所配置模型，模型不可用不会阻止图书导入、阅读或关键词搜索。

## 本地数据

首次启动会在系统为“墨页”分配的 LocalAppData 目录创建 `library.db` 和受管的
`objects/` 目录。删除导入前的外部文件不会影响图书库；需要保留或备份原文件时，
可在图书菜单中选择“导出原件”。

同一个数据目录当前只支持由一个墨页应用进程打开。同一进程内的多个图书库、Reader、
PDF Reader 和 Editor 窗口会通过共享服务有序读写；不要同时启动两个应用进程指向同一
数据目录，否则不保证请求顺序或内存投影一致。

项目目前处于开发阶段，不维护旧数据库兼容性。启动时若发现数据库应用标识、结构
版本、表/索引、完整性或数据关系与当前版本不一致，会删除数据库及受管对象目录并
创建空库；已有图书、分组、阅读进度、索引和 AI 会话都会丢失。升级开发版本前请先
导出需要保留的内容。

## 当前边界

- 对导入内容的修改保存在墨页统一模型中；不承诺写回 DOC/DOCX、PPTX、XLSX、
  MOBI/AZW/AZW3 原格式。
- EPUB/PDF 是统一模型的规范化导出，不保证复刻原 Office、PDF 或 Kindle 文件的复杂
  版式、字体、动画、公式、图表或交互对象；“导出原件”仅适用于导入图书。
- 不支持 DRM Kindle 文件，也不提供 DRM 绕过；加密 PDF 同样会被拒绝。
- 为保证导入后的逐页视觉任务一定可执行，单个 PDF 当前最多 256 MiB、4,096 页；
  超出任一上限会在导入阶段明确拒绝。
- Office COM 增强预览只应对可信本地文件启用。应用会禁用宏和外链更新，也不会主动
  调用宏或 OLE 对象，但 Office 自身对文档和嵌入内容的解析不是安全沙箱。增强页是
  可重建的当前 revision 派生产物；编辑正文或禁用增强后会改用规范化结构化视觉页。
- 不允许书内或 PDF 内容访问外部网络。
- 音频和视频支持本地存储、播放及人工说明索引，当前不做自动转写。
- 当前对象存储仅支持本地文件系统；S3、同步、多设备冲突处理和 AI 写书工具不在本轮范围。
- Windows/MSVC 是当前验收平台，尚未宣称完成其它平台验证。
- 仓库许可证元数据仍有冲突，因此当前不包含打包、发布或重新分发工作。
