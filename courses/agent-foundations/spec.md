它记录预期契约，不是测试通过、真实模型可用或学员学习有效的验收报告。

讲义修订：`2026-09-07.tutorial-1`。本次改为无需外部阅读的连续教程，提供完整示范、

## 目标与边界

面向有基础编程、无 Agent 开发经验的学习者；中文解释，Python 3.12 实验。
一章验证四项能力：解释模型与宿主职责、预测状态变化、诊断并选择恢复策略、
在新的资料与组合故障中迁移。

普通 Python 与 LangGraph `StateGraph` 解决同一个任务，使用相同模型边界、工具、
场景和判定规则。本章只包含只读资料研究；不引入真实网页、个人图书、向量检索、
多智能体、任意依赖安装或后台主动学习任务。桌面复用本章内容与运行协议，使用已单独
验证的 Windows LPAC + Job 执行。CLI 的进程内开发运行只接受本机可信代码，不因此
获得桌面的隔离保证。

完整教程另见 `../ai-agent-tutorial/README.md`。第2—10章的正文与
`tutorial_examples/` 本地示例独立于本章评测接口，不增加本章工具、场景或权限，
也不把本章评分结论扩展到后续章。完整示范直接出现在正文时，跟随示范后的作品应记录
辅助完成；独立重写和新变式仍需单独收集证据。

## 任务与公共边界

任务：根据模拟资料库确认松果项目的试运行日期、对象和允许的操作，逐项引用资料。
全部组织、项目与日期均为虚构 fixture。

| 资料 | 可支持的事实 |
| --- | --- |
| `D1` | `start_date` 为 `2026-10-12` |
| `D2` | `audience` 为 `内部员工`；`allowed_operations` 为 `资料检索与阅读` |

只有两个工具：`search_documents(query: str)` 返回资料 ID 与标题，
`read_document(document_id: str)` 返回正文或结构化错误。搜索标题不是正文证据。
最终 `answer` 必须包含 `start_date`、`audience`、`allowed_operations`；每个字段
都有 `value` 与 `source_ids`：`value` 为字符串或 JSON `null`，`source_ids` 为
资料 ID 字符串数组。未知值不能使用字符串 `"null"`，未知字段的来源数组必须为空。

实现统一导出 `run(task, model, tools, limits, emit) -> AgentOutcome`。
模型调用使用 `model.complete(messages, tools.schemas)`；实际工具调用经过
`tools.execute(call)`，返回与请求 ID 配对的 `role=tool` 消息。工具拒绝也要反馈，
不能让消息历史留下没有对应结果的调用。第三方模型 SDK 类型不进入这个边界。

预算上限为 8 次模型决策、6 次实际工具执行；一次调用暂时失败后至多额外重试一次。
非法工具或参数在执行前拒绝，不计实际执行；已执行但返回错误的工具消耗执行预算。
总运行期限为 `RunLimits` 中的 180 秒上限，由模型/工具边界与参考循环检查；真实
模型单次请求还受剩余期限限制。它不能强制打断任意学生 Python 的死循环或阻塞代码，
桌面另由隔离进程和 Job 执行强制取消与资源限制；CLI 不具备这些保证。
框架自身的图步数不是模型决策次数。

正常结束：`status=completed`、`stop_reason=final_answer`。预算或期限耗尽：
`status=budget_exhausted`，原因分别为 `model_budget`、`tool_budget`、`deadline`。
未完成骨架归类为 `incomplete`，运行异常归类为 `error`；不得把这些状态当成完成答案。
部分事实未知可以形成正常最终答案；它与预算耗尽是不同情况。

## 场景契约

| CLI 场景 | 注入事实 | 学员实现必须表现出的行为 |
| --- | --- | --- |
| `normal` | D1、D2 正常可读 | 通过正文确认三个字段及来源 |
| `invalid_call` | 模型先请求未注册工具 | 宿主拒绝、模型收到错误、后续可以纠正 |
| `invalid_arguments` | 模型先传入不合法参数 | 校验失败后反馈，不进入工具实现 |
| `transient` | 第一次读取 D2 暂时失败，第二次成功 | 只允许一次额外重试，保留 D1 结果 |
| `missing` | 能搜到 D2，但正文永久缺失 | 不反复读取；保留日期，其余字段未知 |
| `transfer` | 更换项目、资料 ID 与事实；搜索先暂时失败，一份正文永久缺失 | 根据运行时资料执行，组合恢复与部分回答，不硬编码 D1/D2 |
| `model_budget` | 模型持续提出不能取得有效进展的决策 | 到达模型预算后停止，不产生伪最终答案 |
| `tool_budget` | 模型持续提出可进入执行的工具调用 | 到达实际执行预算后停止，不执行第七次 |

前三类核心错误是非法调用、暂时失败、永久缺失；非法名称与非法参数分别测试。
公开迁移练习的答案或注入顺序不出现在首次学习讲义中，但源码与规格公开可见，
不能用该场景通过单独证明独立迁移。独立迁移证据由辅导者另外安排未见的等价问题，
保留第一次判断与帮助记录；参与出题的人不能把自己的题目记为未见。

默认用脚本化模型回放形成稳定场景。`live` 使用真实 OpenAI-compatible provider，
仅作为单独记录的探索性冒烟；不混入脚本回放分数，不以一次结果判断能力。
`model_budget` 和 `tool_budget` 只用于 scripted 压力测试。live 非法调用场景若由
宿主替换首个工具请求注入，必须在报告中明确标记，不能描述为模型自发犯错。

## 教学证据与晋级

顺序固定为：先修诊断、轨迹解释、手搓、失败处理、框架配对、迁移与延迟复测。
每一步先教当前必需概念，用已解相似例子展示中间状态，再给小任务和具体自查。
教程中的逐行示范与补全框架属于学习支架，不能把照做后通过记成独立实现。
桌面作答直接使用“预测与作答”，代码实验仅执行完整 `run(...)` 文件；CLI 命令集中在
各课可选末尾。前两步不以“会自行运行参考实现”为开始学习的前提。
每个有意义的尝试先保存预测，再按需使用三级提示。作答只追加，保留作答时间、
代码版本、运行文件、帮助级别和复测日期。
手搓版补全跑通后，先保存原代码快照，再关闭参考与 AI，独立重写“回填结果、继续
或停止”的核心循环。保存未经提示的首次代码与用时，再记录后续提示和修改；这项
同题重建证据不能替代另外安排的未见迁移。

作品门禁：两种实现通过本章八个场景的宿主判定。四项学习能力按
[量规](worksheets/rubric.md) 评分；独立通过要求至少 7/8，诊断与迁移均为 2，
其他项不得为 0。作品通过但学习证据不够，记录“辅助完成”或“待核验”。
安排 2–3 天后复测，可根据实际时间调整；复测前不浏览原解答。初次通过仍待稳定性证据。

宿主可以自动判定模型与工具的实际调用、参数拒绝、预算、退出原因、已读取来源及
结构化答案。学员 `emit` 或打印的日志只用于解释，不能代替宿主采集的事实。
报告的 `provider_usage` 只累加端点成功返回且通过外壳协议检查的用量；
`provider_usage_complete=false` 表示有调用未取得完整用量，不能把该累计值当成
整次运行的确定消耗，更不能推算为确定费用。模型请求尝试仍全部计入决策预算。
宿主不能从测试通过推出因果理解、独立性或专家水平；这部分依据原始预测、解释、
改错与迁移，由人工或 AI 按量规判读，AI 评分保留依据并在首轮人工抽查。

本人开发试学主要验证任务是否可操作、反馈是否可用；出题者已知答案的成绩不能作为
无 Agent 基础学员学习效果的证据。课程、fixture、代码和评分规则变化时记录版本，
不要直接混合比较不同版本成绩。

实际试学状态仍为 **待执行 / trial pending**，使用
[实际试学记录表](worksheets/pilot-session.md) 分别记录开发者亲自跟练与未参与设计
目标学员的首次体验。模板保持空白，不将 CLI 自动冒烟或真实模型调用填写为参与者
学习结果；课程修订必须保留观察依据与前后版本。
