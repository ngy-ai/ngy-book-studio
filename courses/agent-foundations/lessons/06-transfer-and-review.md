# 第六步：换一组资料，检查方法能否继续工作

讲义修订：`2026-09-07.tutorial-1`；实验与评分契约：`1.0.0`。

第五步让同一资料研究分别由普通 Python 和 LangGraph 完成。现在把项目、资料 ID、
事实和故障位置换掉，看看两份程序是否仍能依据运行时反馈继续工作。你会在本步
区分公开练习、独立迁移与延迟复测，并把第一章学到的方法带入后续教程。

## 1. 迁移的对象是方法，不是旧题答案

假设某个程序永远读取 D1、D2，然后写入 `2026-10-12`。它可能碰巧答对松果项目，
但换个项目就失效。可复用的程序应该原样传入本次 `task`，执行模型本轮提出的请求，
把工具实际返回的结果交回模型，再依据这些正文形成答案。

第三、四步完整 `run` 的主体没有写入项目名、D1/D2 或最终事实；第五步也只传状态。
固定数据在课程的模拟资料里，而不是你的控制循环里。程序不必预先知道新 ID，
因为模型在搜索反馈里看到 ID 后会提出对应读取请求，循环只执行这个真实请求。

本章的公开 `transfer` 场景保留相同两个只读工具、消息结构和 8 次模型 / 6 次工具
预算；改变项目、资料与事实，并组合搜索暂时失败和正文永久缺失。你已学过两个
故障各自的处理，现在需要把它们顺序组合起来。本页不提前给出新项目的具体答案。

在运行前先检查自己的两份代码：有没有固定项目名或资料 ID？有没有把期望答案
直接写入返回值？有没有因工具失败清空历史？发现后根据前几步的方法修正，而不是
去新题源码里找一组新的硬编码值。接下来先练一下“证据支持到哪里”。

## 2. 一个完整小题：对象已知，不代表权限也已知

这是独立的纸面例子，不是 `transfer` 中的隐藏事实，也不新增一个桌面可选场景：

> 已成功读取 E11 的正文：“【虚构纸面资料】试运行面向项目维护者。
> 本页未公布开始日期与操作范围。”另一份资料只搜到标题，未读取成功。

你能确认对象是项目维护者，但不能推断开始日期，也不能因为这些人是维护者就
推出他们有修改权限。将结果用本章格式表达，完整的 Python 示例是：

```python
import json

answer = {
    "start_date": {"value": None, "source_ids": []},
    "audience": {"value": "项目维护者", "source_ids": ["E11"]},
    "allowed_operations": {"value": None, "source_ids": []},
}
print(json.dumps(answer, ensure_ascii=False, indent=2))
```

打印时 `None` 会变成 JSON 的 `null`。只有对象字段引用 E11，不能把一个确实存在
的来源贴在所有结论旁边。来源需要同时满足两个条件：本次确实成功读取；正文实际
支持这一字段。这里的字典是纸面答案演示，不是把事实写死进 Agent 的 `run`。

自查变化：如果又成功读到 E12，正文明确说“允许目录检索”，会改变哪些字段？
答案：只把 `allowed_operations` 改为 `{"value":"目录检索","source_ids":["E12"]}`；
对象保留 E11，日期仍未知。新证据补充某一字段，不会自动证明其它字段。
带着这个判断方式，再去看公开迁移的真实运行。

## 3. 第一次运行前，留下你预期的策略

在“预测与作答”写下这次准备检验的判断，不用预先猜新题事实：

```text
搜索暂时失败时：只在明确允许重试且预算未耗尽时额外尝试一次。
获得搜索结果后：执行模型根据本次结果提出的读取请求，不替换成旧 ID。
一份正文永久缺失时：回填最终错误，保留此前成功正文。
回答时：已知项须有实际读取且支持该项的来源，其他项保持未知。
额度耗尽时：保存原始停止原因和已有消息，不伪装成完成。
```

这是已经讲解过的策略示范。用自己的话重述最不确定的一项，记录你看过哪些代码
和提示。首次运行前的预测即使错误也有价值，因为后面可以比较自己究竟改变了什么。
如果已经看过场景源码或他人的结果，如实写“已见设置”，仍然可以练习。

在桌面选择“Python 手搓”和“公开迁移练习”，运行第四步的修复版或自己的对应实现。
先看一次完整结果，不立即反复重跑。下一节说明报告里应该沿什么线索阅读。

## 4. 从工具记录读出实际发生的事

沿“逐步轨迹”按顺序找这四类证据：

| 你要确认的问题 | 看什么记录 | 为什么只看最终答案不够 |
| --- | --- | --- |
| 本次任务有没有传入 | 第一次模型收到的 user 消息 | 旧任务也可能生成格式正确的答案 |
| 是否使用当前资料 | 搜索返回 ID 与随后模型提出的读取请求 | 固定旧 ID 可能读不到本次正文 |
| 失败是否按规则处理 | 错误 code、retryable、每次实际执行与最后回填 | 同样答案可能经历过非法重复或遗漏反馈 |
| 每个结论是否有依据 | 成功读取记录、正文、最终 source_ids | 引用了真实 ID 也可能不支持对应字段 |

`actual_execution=false` 表示请求被拒绝，不能算读过正文；`true` 表示确实进入
工具操作，但仍要看 `result.ok`。读取返回 `NOT_FOUND` 时，消耗一次执行，成功
正文证据却没有增加。计数与知识增加并不是一回事。

再切换“LangGraph”运行相同场景，比较两份报告的任务、模型和工具次数、重试、
答案与来源、停止原因。第二份运行时已经见过第一份结果，记录这种帮助即可，
不必把两次都说成首次未见。框架节点计数另看，不当成模型决策数。

桌面一次运行一个实现，通过“历史”选择记录对照；没有自动配对或自动评阅解释。
这一限制不会阻碍你自学，前文已经给出判断依据。运行结果是作品证据，你的解释
和修复过程则说明你如何理解它。下面用一个故障诊断例子把两者连起来。

## 5. 答案错了，先找能区分原因的记录

假设最后来源检查失败。可能是程序仍读取旧 ID，也可能是新正文已读到，却被你
重新赋值 `messages` 丢掉。两种原因看起来都像“答案没依据”，修复位置却不同。

先查真实读取请求和结果。如果请求中仍是旧 ID，回到传入任务与执行模型原始调用
的代码；如果新资料读成功，再查看下一次模型输入是否保留该条 tool 消息。后一种
应该修消息保留，改最终答案文字不能补上丢失的过程。

一次具体修复记录可以写成：

```text
观察：读取新资料成功，但下一次模型输入只有最后一条工具消息。
假设：我在每轮开始把 messages 重新赋值，旧历史被覆盖。
修改：只在 run 开始建立 messages，循环内追加新消息。
预测：下一次模型输入应包含原任务、搜索、两份读取结果。
复验：检查是否出现预测的完整历史，再看来源检查是否通过。
```

这是示范记录，不要把它当成自己确实遇到过的故障。自己的记录需要保留真实的
首次预测、最早差异、修改和复验。一次只修证据支持的最早问题，能降低来回乱改
造成的混淆。反复卡住时，回第四步的单故障场景，缩小问题再带回组合场景。

## 6. 现在能说明什么，仍不能说明什么

如果公开场景通过，你可以说：“这份代码在这些任务与故障下符合检查要求。”如果
还能解释每个分支、预测变化并修好自己的错误，理解证据就更充分。由于课程、代码
和示范公开，公开题通过不能单独证明在完全未见问题上的独立迁移，更不能自动
产生“专家”结论。

有辅导者时，可以另给一道保持相同工具和预算、仅改变资料与失败位置的新题，
保留未提示的首次作答。没有辅导者也可以继续学习后续章节，把“未见迁移”记为
待核验，不需要为等待测评停在这里。

先完成三个公开自查，答案在下面：

1. 同轮第二个工具永久失败，第一个成功结果会失效吗？
2. 工具标记可重试，但总执行已经 6 次，是否允许额外执行？
3. 预算耗尽后，能否猜完剩下字段并返回 `completed`？

答案依次是：不会，应保留每个调用各自结果；不能，重试仍受总额度约束；不能，
要返回准确的预算停止原因与 `answer=None`，历史仍保留。正常部分答案与预算停止
区别在第四步已经完整演示。如果解释仍含糊，就重读对应一节并在代码上指出位置。

## 7. 几天后再解释一次，而不是只确认“眼熟”

可以在笔记安排 2–3 天后复测，日期按你的学习节奏调整。系统目前不会自动排期或
推送学习任务，因此把时间记下来即可。复测先不看原代码，做这个完整纸面题：

> 一个查询请求第一次超时且明确可重试；第二次返回“没有该任务”，明确不可重试。
> 画出执行和回填顺序，标出工具执行次数。能够据此说“任务已完成”吗？此前其它
> 已成功取得的资料应该怎样处理？

答案：同一请求实际执行两次，只回填第二次最终失败，不再第三次尝试；“没有该任务”
不能推成“任务完成”，其它成功结果保留。这个问题仅检验推理，不向本章新增工具。
然后打开代码，指出有限重试、最终回填、历史保留、预算停止的位置。

如果说得对却找不到代码，说明还需要把概念与实现连接；如果代码会写却判断错，
回到证据与失败含义的解释。复测用于发现下一项具体要补的能力，不抹去已有作品。
到这里，第一章的主要学习闭环已经完成，最后再说明真实模型与后续章节的关系。

## 8. 真实模型观察与后续学习

固定响应模型让你稳定复现控制流；真实模型会选择不同的调用顺序，也可能产生
不合规 JSON。此时优先区分消息格式、工具行为、事实与来源四种问题，不要将所有
错误都归结为模型能力。真实运行也不能放宽预算或跳过来源检查。

桌面第一章实验仍使用固定响应模式。有已配置的兼容端点时，可在交互终端做可选
观察。以下命令在课程目录执行，端点、模型名和工作区路径必须替换为自己的配置：

```powershell
uv run --locked python -m ngy_lab credentials set --base-url https://your-provider.example/v1
uv run --locked python -m ngy_lab run --implementation workspaces/first-agent/manual.py --scenario normal --mode live --base-url https://your-provider.example/v1 --model your-tool-capable-model --allow-remote
```

第一行隐藏输入课程专用凭据，并存入 Windows Credential Manager；不写进代码、
环境变量或作答。`--allow-remote` 明确允许向指定远程端点发送本次虚构资料；
远程 HTTP 另需 `--allow-insecure`。本机回环端点无需远程许可。课程不会自动启动
模型服务或下载模型；真实端点不是读懂本章或进入后续教程的必需条件。

命令行在当前进程执行指定代码，只用于可信本地开发；桌面的隔离执行边界不适用于
CLI。保存原始运行记录，比较两版耗时、调用量和轨迹，真实模式结果与固定场景检查
分开记录。上述示例不保证所有端点都支持相同参数，应先确认端点支持工具调用。

回看六步：你从资料与 Python 数据结构开始，读懂真实消息协议，亲手组织循环，
加入有界失败处理，再用图表达相同行为，最后用新资料检查方法。这是继续学习模型
接口、检索、记忆、规划和工程评测的基础。进入[完整教程](../../ai-agent-tutorial/README.md)
继续后续章节；后续正文和本地示例可以独立阅读运行，第一章桌面自动评测仍单独保留。
