# 参考解答：首次作答后再阅读

这是独立的解答文件。需要完整示范时可以直接查阅；之后把当前任务记为辅助完成，
再用一个新的问题检查理解。不要覆盖之前的错误预测。

## 第一步：Python 诊断

A：`first == 1`、`second == 2`，最后 `state == {"seen": ["D1", "D2"]}`。
函数内的 `append` 修改的是同一个列表。如果函数开头重新执行
`state = {"seen": []}`，两次返回都是 1，外部 `state` 仍为 `{"seen": []}`；
局部名字改指向新字典，没有修改外部字典。D2、D2 的变式会得到重复的两个 D2，
列表不会自动去重。若业务要求每份资料只记录一次，可先检查是否已存在或另存集合，
但工具的执行轨迹不应随意去重，否则会隐藏重试与重复调用。

B：`events` 为 `[('D1', '日期已确认'), ('D2', 'retry_later'),
('D3', '日期已确认')]`。`continue` 开始下一轮；换成 `break` 后没有 D3 记录。
静默捕获会使调用者无法区分“没有资料”与“获取资料失败”，后续决策也失去依据。

C：`call["arguments"]["document_id"]`。键存在不代表值符合接口要求，整数 42
不满足字符串 ID 约定。实际工具边界还要拒绝缺字段、意外字段或其它不合法结构。

## 第二步：正常轨迹

给定教学轨迹中，模型分别决定搜索、同时请求读 D1/D2、回答，共 3 次模型决策；工具
执行 3 次。一次模型响应可以有多个调用。任务文本只提出问题，不携带已验证答案。
搜索只得到资料身份；读 D1
后只确认日期；读 D2 后再确认开放对象与操作范围。消息历史应保留两份正文。

模型提出请求，宿主检查工具及参数并决定是否执行。调用成功或被拒绝，都需要有
对应调用 ID 的结果；模型不能自行签发执行许可。预算由宿主阻止越界，不依赖
提示词中的“请不要超过”自行生效。

正常最终答案：

```json
{
  "start_date": {"value": "2026-10-12", "source_ids": ["D1"]},
  "audience": {"value": "内部员工", "source_ids": ["D2"]},
  "allowed_operations": {"value": "资料检索与阅读", "source_ids": ["D2"]}
}
```

## 第三至五步：实现与失败策略

完整参考实现分别在 [manual.py](../ngy_lab/implementations/manual.py) 和
[langgraph_agent.py](../ngy_lab/implementations/langgraph_agent.py)。
[common.py](../ngy_lab/implementations/common.py) 包含协议检查和单步处理。
先把你自己的控制流画出来，再对照参考；不要只把参考导入自己的 `run` 后称为完成手搓。

正常循环的关键是完整追加 assistant 消息、处理本轮所有工具调用、回填最终工具
消息，然后重新调用模型；没有调用时校验最终结构并退出。框架版把同一循环放在
节点和边上，工具策略、消息协议、来源与预算没有因此消失。

| 现象 | 适合本章的解释与处理 |
| --- | --- |
| 未注册工具或错误参数 | 执行前拒绝，把错误回填；不猜测另一个工具代替执行 |
| D2 一次暂时失败 | 确认 `retryable=true` 后额外执行一次，保留 D1；把最终工具结果反馈 |
| D2 永久缺失 | 不重试，不依据标题补写；日期可保留，其他字段为 null 与空来源 |
| 模型继续调用但模型预算耗尽 | 返回 model_budget，不再作下一次模型决策 |
| 即将需要第七次真实工具执行 | 返回 tool_budget，不实际执行第七次 |

`transient` 的额外执行发生在同一调用处理里，正常参考路线仍是 3 次模型决策，
但工具执行从 3 次变为 4 次。一次调用对应一条回填给模型的最终 tool 消息；
两次尝试仍都要出现在宿主执行证据中。不能用少了一条对话消息推断重试没有执行。

部分答案的“完成”与预算耗尽不同：`missing` 可以用已确认日期和两个未知字段正常
结束；预算耗尽必须保存实际停止原因。最终内容相同也不证明两版行为相同，要检查
执行顺序、拒绝与重试、来源以及预算。

框架选择题没有唯一品牌答案。对小型固定循环，普通 Python 可能更便于看清执行；
当分支、状态流转与人工确认变多时，显式图可能更便于组织。有效答案必须说清当前
约束与改变选择的条件，不能只说“框架更先进”。

## 第六步：公开迁移练习与复测

公开 `transfer` 使用不同项目与资料，搜索有一次暂时失败，一份正文永久缺失。
应先有限重试搜索，使用它实际返回的 ID 读取资料，再只保留成功正文支持的事实。
不能复制松果项目答案。公开源码或本文件中的信息使它不具备保密测评条件；独立
迁移仍需要另外安排未见变式。

若暂时错误重试后变成永久缺失，本次不再重试，向模型回填最终失败；实际执行了
两次工具。模型可以说明未能确认该任务或资料，不能把“没有该任务”改写成任务
已完成，更不能把历史记录当作当前状态。既有其它成功来源应保留，最终表述与
能够证明的范围一致。

延迟复测不能只看答案是否熟悉。看学员是否能在不翻原代码时画出执行与反馈顺序，
解释计数和未知边界，再在代码中定位对应策略。若只记住措辞却无法定位实现，
下一步应回到轨迹与状态练习。
