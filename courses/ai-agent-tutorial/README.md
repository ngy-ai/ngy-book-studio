# 从零构建 AI Agent：原理、工程与独立实践

教程修订：`2026-09-07.tutorial-2`。适合会写简单程序、尚未开发过 Agent 的学习者。

这是一套可以按顺序独立阅读的中文教程。需要理解的概念、演算过程、关键实现、
示例结果和练习解释都放在正文里；不用先读参考图书，也不用一边猜术语一边翻框架源码。
正文中的外部链接用于进一步查证和延伸，跳过它们不影响完成本章。

## 先认识我们要构建的东西

假设有人问：“松果项目什么时候试运行，谁能参加，可以做什么？”
如果答案没有放在问题里，普通的一次模型回答可能凭已有知识猜测。
我们需要让程序先找到资料、读取正文，再根据取得的证据回答。如果工具失败，它要区分哪些事情已经知道、哪些仍然未知，并在合适的时候停止。

本教程把 **AI Agent** 理解为这样一个程序：模型根据当前信息提出动作，程序检查并执行动作，把结果交给模型，再决定继续还是结束。

- 模型是决策者之一；
- 工具调用、消息保存、权限检查和停止条件都需要程序实现。

第一章用固定的模型响应代替真实模型，让每一步都能稳定重现；它是用来观察机制的教学替身，不具备真正的语言理解能力。
我们从这个小研究助手开始。每章保留此前理解的核心，再增加一个现实问题。例如，第一章只需要两份资料，第三章才讨论几十份资料怎样筛选；第一次运行不用记忆，第四章才讨论怎样保留可信信息；单人任务够用时先不增加多 Agent。

所有组织、日期、文档、用户和草稿都是虚构教学数据。默认示例在本地离线运行，不读取个人图书库、不发送邮件、不操作真实业务系统，也不需要 API 密钥。

第一章分为六节：准备必要的 Python → 推演完整循环 → 手搓 → 故障处理 → LangGraph 重建 → 迁移。六节共同构成第一章，不是六个平行的小课程。
第2—10章则各有连续正文、独立的桌面代码任务，以及包含两种实现的本地示例。

这里的 **手搓** 指亲自实现关键机制，观察状态如何变化；**库版本** 指用成熟库承载同样的机制，并看清库承担了哪些工作。两种实现可以共享资料和小函数，但不能把运行手搓代码的一个大函数随便包成图节点，就当作理解了框架。

## 如何阅读，才不会被代码打断

每章先读问题和一个具体例子，随后再看代码。代码前会交代它接收什么、返回什么、
在整个流程的哪个位置；代码后解释状态如何改变，以及哪些输出是预期的。
先按示例推演一遍，再合上解释自己回答练习，最后用就地自查核对理由。

遇到程序结果与你的预测不一致，保留第一次预测，指出分歧从哪一步开始。不要只把
答案改成程序输出；例如“我把工具请求当成工具已执行”就是一个能指导下一次练习的
具体原因。“我不懂 Agent”则太宽，无法帮助你修改代码。

正文给出的完整代码是教学示范。跟着它跑通，说明环境和示范能工作；独立实践要换
一份资料、改变一个约束，或者在不看示范时重建关键函数。自查答案和完整示范就在
当前章，你可以按需要使用，再如实记录使用了什么帮助。

## 在墨页中学习

从图书库左侧“学习中心 · AI Agent”进入，默认打开本教程总览。左侧“完整教程 · 十章”
可以直接打开各章，正文顶部有上一章、下一章。第一章还有六步讲义入口。

第一章使用“开始第一章”或“继续第一章”进入现有练习，在“代码实验”中编辑、运行，
在“预测与作答”中记录判断，右侧查看结果与轨迹。六步位置和此前作答继续保存在原有
第一章学习档案中。

第2—10章从正文顶部的“本章代码实验”进入本章练习。“讲义”说明当前任务的输入、
可用动作、返回结构与检查规则；在“代码实验”选择“Python 手搓”或“库实现”并编辑，
在“预测与作答”保留运行前的判断。章节各有自己的代码与学习记录；切换章节先保存
当前章，再载入目标章，阅读正文不会把第一章代码替换成示范。
练习中用“本章正文”回看概念，再回到实验继续编辑。顶部保存、导出和恢复按钮标明
当前实验章号；备份只能恢复到同一章。恢复来的运行报告显示待核验，需要重新运行
才能补上本机检查证据，不能将别章的通过记录当成本章成绩。

第2—10章都提供“正常任务 / 故障练习 / 迁移挑战”，对应 `normal / fault / transfer`；
第一章保留工具调用循环所需的八个场景。正常任务先检验关键机制，故障练习加入需要
识别、恢复或拒绝的条件，迁移挑战再改变资料或组合约束。场景名称不是答案标签，
最终状态要根据本轮输入和实际工具结果计算。
资料标识和部分事实在运行时生成，不要把示范里的 D1、日期或完整输出写死。
“正确拒绝”也可能通过检查，例如未批准时保持零份草稿；不要为了得到 `completed`
就绕过拒绝和未知状态。

### 桌面编辑的函数与本地示例有什么区别

桌面两种实现都编辑同一个形式的入口：

```python
def run(task, model, tools, limits, emit):
    # 在这里实现本章任务，返回 AgentOutcome。
    ...
```

`task` 是任务文字；第2—10章的 `model` 提供一次宿主生成的本轮输入，用于稳定练习，
不是真实大模型推理；`tools` 只开放本章允许的动作；`limits` 给出执行限额；`emit`
让你补充解释轨迹。入口返回 `AgentOutcome`，其中 `answer` 的具体形状见本章练习讲义。
自己的 `emit` 日志不是成功执行证明，最终检查还会使用宿主记录的实际动作与状态。

一次桌面运行最多允许八次模型接口调用和六次实际工具执行；第2—10章只应取得一次
练习输入，后续由你的程序处理。只有明确标为可重试的错误，才允许额外尝试一次。
某些任务还有更小的局部预算，例如第五章的步骤数；必须同时遵守两层上限。
框架节点数量另行展示，不能当成模型调用数或工具执行数。

输入通过 `model.complete(messages, tools.schemas)` 取得。`messages` 初始为
`[{"role": "user", "content": task}]`；返回消息的 `content` 是 JSON 文本，解析后有
`chapter`、`case_id`、`scenario`、`input`。前三项标识本章、本轮和场景，`input`
才是待处理的数据。这里不会提供应交回的整份作业结果，也没有让模型代写作业的后续对话。
第六章的 `gold` 是评分任务本身的输入，你仍需根据它计算各项检查，不能把标签当作评分结果。

起始代码中的 `ngy_lab.chapter_support` 只封装公共协议：`load_case` 取得输入，
`call_tool` 组装调用并解析结果，`finish` 封装交卷。它们不实现本章算法。
多数起始代码把作业再分成两个小函数：`prepare(data)` 接收本章 `input`，返回你设计的
判定或计划；`perform(data, plan, state, tools)` 接收这份中间结果，执行允许的动作，
返回本章讲义规定的 `result`。看到 `NotImplementedError`，表示这部分正等你补全，
不是环境缺少依赖。第五章库版改为由图反复调度单步执行，具体分工见该章练习。
工具调用保留标准 `id / type / function` 外壳，`function` 内是工具名称和 JSON 参数文本；
调用 ID 使用本轮 `case_id` 加冒号及递增派发序号，不能沿用上一轮 ID。
返回消息的 `content` 解析后是 `ok/data` 或 `ok/error`，先检查 `ok` 才能使用数据。

交卷结果的外层固定为 `AgentOutcome("completed", "final_answer", answer, messages)`，其中
`answer={"case_id": 本轮ID, "result": 本章结果}`。外层 completed 只表示函数交出了结果；
业务是否完成、应当拒绝还是应当保留未知，要看本章 `result` 和宿主检查。即使你自行
填写 `passed=True`，也不能替代宿主评分。

`messages` 必须保留原始 user、输入 assistant，以及每次工具调用的 assistant 和 tool
消息。使用 `load_case / call_tool / finish` 会维护这些外壳；若自己拼协议，也必须完整
回填。消息链与宿主观察不一致会导致检查失败，答案文字正确不能替代执行记录。

手搓实现与库实现在各自编辑区独立保存。桌面库版按本章任务使用参数模型或图节点组织处理；
正文还提供更完整的机制演示，例如工具装饰器、第七章的中断恢复。
使用库仍要保留本章的权限、证据和停止规则。
不要在一个图节点里调用整份手搓流程，就把它当成完成了机制对照。

本地 `tutorial_examples/chNN_*.py` 中的 `run_manual()`、`run_framework()` 是完整演示入口，
不接收桌面的运行接口，不能整份粘贴到桌面提交。桌面起始代码已准备好必要入口；先按
练习讲义补全，再查看参考实现。运行参考、复制示范或接受完整 AI 答案应记录为 `S`，
不能改记为 `H0 · 独立尝试`。H1—H3 用于如实记录定位、结构和局部实现提示。

建议先保存首次预测，运行自己的手搓实现，定位第一处分歧，再用库重建同一机制。
最后在迁移变式中解释哪些规则保持不变，隔几天不看参考重做关键部分。运行报告证明
本次代码对这些输入的表现；你的理解与独立完成程度仍需结合预测、解释、帮助记录和复测。

## 一次准备，运行所有本地示例

环境是 Python 3.12 与 uv。已有第一章环境即可复用。uv 是管理 Python 环境和依赖的
命令行工具；如果终端找不到 `uv`，先按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)
完成安装并重新打开终端。这个链接仅用于工具安装，不承担 Agent 知识讲解。

在仓库根目录执行：

```powershell
Set-Location courses/agent-foundations
uv sync --locked
uv run --locked python -m tutorial_examples --chapter 2
```

`Set-Location` 切换目录；`uv sync` 按依赖锁准备环境；`--locked` 要求保持锁定版本；
`python -m tutorial_examples` 运行教程的示例入口；`--chapter 2` 选择第二章。
首次安装依赖需要联网，示例执行本身不请求远程模型。

把数字改成 3 到 10 可运行对应章。不传章号会依次运行全部九章：

```powershell
uv run --locked python -m tutorial_examples
```

每份结果分别显示 `manual` 和 `framework`：前者是手搓，后者是库版本。
“两版输出一致”只表示这组确定输入的可观察结果相同；它既不是性能比较，也不是对你
独立掌握程度的评分。若示例启动失败，先确认当前目录和 `uv sync --locked` 是否成功。
若报“找不到模块”，不要把文件随意搬进桌面工作区，应从上述目录使用同一命令重试。

全部示例位于 `courses/agent-foundations/tutorial_examples/`，复用该目录的 `uv.lock`，
没有第二套依赖锁。这些命令执行的是仓库中可审阅的教学代码，属于普通本地 Python
运行；桌面执行器的隔离和资源限制不自动适用于命令行示例。

## 学到什么程度，怎样继续

读完教程，你应能解释并重建工具循环，处理错误，设计证据和记忆流程，用对照用例
评价系统，并说明某个场景是否需要规划、多 Agent 或 MCP。综合项目要求你把这些
能力放在同一份作品中，再用新资料和故障变式检验它们。

走向专家还需要更长时间的真实任务、稳定结果、独立取舍和同行反馈。第十章会给出
怎样提出改进假设、做消融实验、保存复现材料的方法。这里不以阅读进度、测试通过数
或一次大模型评分授予“专家”结论。
