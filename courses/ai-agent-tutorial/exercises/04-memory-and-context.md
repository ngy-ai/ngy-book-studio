# 第四章桌面练习：先筛选可信记忆，再读取内容

本次集中练习记忆的读取门槛：当前用户、当前项目、有效期、核验状态与是否被替代。
正文还讲更正写入与来源重新核验；这个桌面任务先不实现它们，也不测试跨进程持久记忆。
先把“哪些记录根本不能进入上下文”做正确，避免相关性掩盖归属或过期问题。

## 编辑入口和本轮输入

从第四章正文点击“本章代码实验”，编辑本章 `run(task, model, tools, limits, emit)`。
使用起始代码的 `load_case` 取得 `state`，输入在 `state["case"]["input"]`。
最终用 `finish(state, result)` 交卷，保留宿主核对所需的消息链。

输入含 `user_id`、`project_id`、`now` 和 `records`。`now` 是教学逻辑时间，不是系统日期。
每条记录只有元数据，没有记忆正文值：

```json
{
  "id": "本轮记忆ID",
  "user_id": "所属用户",
  "project_id": "所属项目",
  "expires_at": 200,
  "verified": true,
  "status": "active",
  "field": "preference"
}
```

`verified` 由宿主样本提供，不是模型可以自行提升的权限。`field` 说明内容的用途，
例如偏好或练习模式；它不包含该记忆的实际值，不能直接当作回答。

## 五个条件同时成立才能读

逐条检查：用户相同、项目相同、`expires_at > now`、`verified is True`、
`status == "active"`。到期时刻就无效；`superseded` 表示已有更正，不再用于当前召回。
把通过的记录按 `id` 字符串升序排列，再依次执行：

```python
payload = call_tool(state, tools, "read_memory", {"memory_id": record["id"]})
```

成功结果形如 `{"ok": True, "data": {"memory_id": ..., "value": ...}}`。
只有这里取得的值才能加入最终结果。不能先把六条内容全读出来再筛选；
即使最后没有显示别人的记忆，读取边界也已经错了，宿主会拒绝。

举例：当前时间 100，一条相同用户和项目的记录在 100 到期，即使其值非常有用也不应读取。
另一条在 200 到期但状态为 superseded，也不应读取；这两次拒绝的原因不同。

## 输出与两个实现

`result` 只有 `selected`，按已选记录的 ID 顺序返回：

```json
{
  "selected": [
    {"id": "实际记忆ID", "field": "该记录的field", "value": "工具返回的value"}
  ]
}
```

没有合格记录时，合法结果是 `{"selected": []}`，并且不调用任何 `read_memory`。
这表示本轮没有可用记忆，不表示用户没有偏好、项目不存在或历史记录是假的。
多条合格记录即使用同一个 field，也要按各自 ID 保留。本任务返回可用记忆列表，
尚未要求你在同字段记录之间选出唯一偏好；不能用字典覆盖悄悄完成这个取舍。

手搓版先形成合格记录列表，再读取值。库版用 LangGraph 的准备节点保存该列表，
执行节点只读取列表中的记录并组织输出。图状态与长期存储是不同概念；
这次用了图也没有自动实现记忆写入、语义检索或磁盘恢复。

## 三个场景怎样变化

| 场景 | 合格记录与真实读取 |
| --- | --- |
| 正常任务 `normal` | 六条记录中有 1—2 条合格，只读取合格记录 |
| 故障练习 `fault` | 六条中有 0—2 条合格；全部不合格时应返回空列表且不读取 |
| 迁移挑战 `transfer` | 六条中有 1—3 条合格，记录用途与失败原因重新组合 |

每次的当前时间、ID、字段、值与列表顺序都会变化。ID 不编码可用性或失败原因；
必须对本轮每条记录应用五个条件，不能按场景名、ID 后缀或下标推断读取集合。
所有被拒绝记录的内容都留在宿主，不应通过猜测填进输出。

没有可用记忆时应返回什么。然后补全手搓版，先看实际读取集合，再看最终 selected。

自查：`expires_at == now` 已过期；superseded 只表示退出当前使用；没有可用记忆应返回空列表。
