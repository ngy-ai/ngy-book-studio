# 第三章桌面练习：从候选取得证据，再判断冲突

输入给出一批资料的目录元数据，但没有直接给出它们的事实。你需要先在授权范围内筛选
相关资料，再实际读取，最后区分一个被支持的值、没有证据和互相冲突三个状态。
本次把分块和词项抽取预先完成，集中练习候选、读取与答案之间的边界。

## 入口与输入

从第三章正文点击“本章代码实验”，在“代码实验”编辑本章的五参
`run(task, model, tools, limits, emit)`。起始代码的 `load_case(task, model, tools)`
返回 `state`，数据在 `state["case"]["input"]` 中。

| 输入字段 | 意思 |
| --- | --- |
| `fields` | 本轮要回答的字段，例如 `date / audience / operations` |
| `query_terms` | 本轮查询的词项列表 |
| `allowed_ids` | 本轮授权资料集合 |
| `documents` | 候选列表，每项是 `{"id": 资料ID, "terms": [词项...]}` |

正文完整示范使用 `start_date` 等字段；桌面以本轮 `fields` 为准。
目录的 `terms` 不是资料正文，命中不表示已经读到事实，也不能直接填入答案。

## 先决定读什么，再实际读取

选中条件有两项，必须同时成立：资料 ID 属于 `allowed_ids`，且该资料 `terms` 与
`query_terms` 至少有一个交集。把选中的资料 ID 按字符串升序排列，每份只读取一次。
这次没有 top-k 截断，也不按相似度猜权威性；目标是收齐所有符合此规则的授权证据。

通过公共助手调用：

```python
payload = call_tool(state, tools, "read_document", {"document_id": source_id})
```

成功的 `payload["data"]` 含 `document_id` 和 `facts`。只把成功读取的 `facts` 加进证据表。
三种场景中筛选后的读取都能成功；无关或越权候选不应拿来试读。
宿主独立记录读取，不接受在最终结果中自报“这些资料我都看过”。

## 聚合每个字段

对 `fields` 中每个字段，从已读证据收集包含该字段的来源及其值。按不同值分组后：

| 值的情况 | `status` | `value` | `source_ids` |
| --- | --- | --- | --- |
| 没有来源包含该字段 | `unknown` | `None` | 空列表 |
| 一个不同值，可以由多个来源共同支持 | `supported` | 该值 | 所有支持来源，按 ID 排序 |
| 两个或更多不同值 | `conflict` | `None` | 所有发生冲突的来源，按 ID 排序 |

注意这个桌面结构显式带有 `status`：冲突时 `source_ids` 用于指出需要复核的冲突来源，
并不声称这些来源支持某个已选定的值。它与正文短例子“空来源加 alternatives”的表示不同。
不能把冲突直接丢成没有证据，也不能因文件名更大就选择一个日期。

结果交给 `finish(state, result)`，其中 `result` 形如：

```json
{
  "fields": {
    "date": {"status": "conflict", "value": null, "source_ids": ["来源A", "来源B"]},
    "audience": {"status": "supported", "value": "受邀员工", "source_ids": ["来源C"]},
    "operations": {"status": "unknown", "value": null, "source_ids": []}
  }
}
```

这是结构示意，ID 与值必须从本轮取得。不能用此示意直接交卷。

## 手搓与库版本

手搓版分成筛选、读取、聚合三步。先在纸上列选中 ID，再对照实际工具轨迹。
桌面库参考用 LangGraph 分开两个阶段：准备节点形成待读列表，执行节点读取并聚合字段。
图状态保存列表与最终结果；执行节点内的证据表逐条累积，不能被后一次读取覆盖。
也可以将读取与聚合再拆成节点，但状态更新必须保留此前取得的证据。
本练习要求按排序后的 ID 顺序调用工具，不要为演示并行而引入不确定的读取次序。

| 场景 | 预期行为 |
| --- | --- |
| 正常任务 `normal` | 读取两份相关授权资料，三个字段都有一个支持值 |
| 故障练习 `fault` | 多读一份矛盾日期资料，日期为 conflict，其余字段仍可 supported |
| 迁移挑战 `transfer` | 对象资料变为无关候选，只读取日期来源；对象与操作为 unknown |

其他作用域的候选即使词项完全匹配，也不进入读取。宿主会检查动作数量、身份和顺序。

## 首次尝试与提示

运行前写出：哪些候选会被筛掉；日期冲突时你会保留什么；为什么 unknown 不能解释成
“项目没有受众”。先完成手搓，再用库重建，最后运行迁移场景并比较最早变化的步骤。

H1：分开列“目录可见”“本轮授权”“相关”“实际读到”四个集合。H2：先生成排序后的
待读列表，再写字段聚合。H3：只查看参考的一个字段聚合，自己完成整条流程。

自查：无关资料未读取，表示本轮没有取得这项证据；冲突表示已经有相反证据。
两者都可能返回 `None`，原因和下一步却不同。保留首次预测和提示级别，完整参考运行记 S。
