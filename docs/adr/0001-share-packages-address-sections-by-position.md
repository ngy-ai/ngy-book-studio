# 分享包的分区按章节序号定位，不写发送方的 ID

分享包要把笔记、AI 问答和译文交给另一台机器，而库里的 ID 全部由内容派生：book id 是导入原件的内容哈希、unit id 由 book id + 序号 + href 派生、块标识又由 unit id 派生（`deterministic_id`）。对方即使拿到逐字相同的文本，只要原件不是同一个文件，就会得到另一套 ID。所以分区条目只写**章节序号**加原文引用，导入时按接收方自己的文档逐条复验（笔记比对阅读章节正文的 UTF-16 范围，译文重挂到接收方的块形状，引用重建成接收方自己的 locator），对不上的条目逐条丢弃并在结果里报数，绝不按引文搜索重定位。

## Consequences

- 导入天生是「部分成功」：结果是计数，不是全或无。
- 章节数对不上时必须整批放弃分区——序号会指向别的章节；这条闸门在「复用已有图书」和「落投影」两条路上都要过。
- PDF/DjVu 页面笔记锚在 PDF.js 页面文字层上，在「落投影」路上无法用章节正文复验，因此不迁移；只有在接收方拥有同一本原件、走复用路时才按页面规则导入。
- 代价是**包一旦发布就很难改回 ID 定位**：格式版本要跟着升。
