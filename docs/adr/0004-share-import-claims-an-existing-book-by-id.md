# 导入先按发送方的图书 ID 认领已有的书

所有导入器的 book id 都是 `deterministic_id("book", 原件内容哈希)`（EPUB/PDF/Office/Kindle/KFX/DjVu 一致），所以**同一份原件在两个库里是同一个 ID**。分享导入因此先查 `manifest.book.id`：命中就直接复用那本书，不再导入包里的投影；未命中才把投影发布成新书。这本是「朋友也早就买了同一本书」的常见情形，而现在的做法会给对方多出一本内容相同、ID 不同的书——那是用户最难自己修好的状态。

## Consequences

- 复用路径上两侧的 book、unit、块 ID 完全相同，因此引用可以**保留发送方块级 locator**（导入前逐条复验），PDF 页面笔记也能按页面规则导入。
- 复用路径不改变图书的分组，也不刷新本地修订：写入的只有分区。
- 命中依赖 ID 相同，因此应用内「新建图书」的书（ID 来自标题与时间戳）永远走投影路。
- 误判风险等于 BLAKE3 碰撞：ID 相同即字节相同。
