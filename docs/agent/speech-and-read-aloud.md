# 朗读（Windows 系统语音）

> 本文件由根 `AGENTS.md` 拆分而来；全局约束与文档索引见根 `AGENTS.md`。

## 是什么

三个阅读窗口与 AI 问答侧栏都支持朗读（TTS），共用一套引擎、互斥规则与生命周期：

- **EPUB 阅读窗口**（含规范化后的 Office/Kindle 阅读）：鼠标移到段落上会出现小喇叭，
  点它从该段开始按顺序读；工具栏的「朗读」从当前可见段落开始，播放中换成「暂停/继续」
  与「停止」。读到章末停止（跨章续读不做）。
- **PDF 阅读窗口**：工具栏的「朗读」从视口里第一段可见的文字开始；文字来自 PDF.js 的
  文字层，段落按行距把相邻行合并（PDF 没有段落语义），读到**已绘制页面**的末尾停止。
- **页面图片窗口（DjVu）**：「朗读」把当前页的隐藏文字层读完，右侧「本页文字」面板里的
  当前段落高亮；翻页即停。
- **AI 问答侧栏**（`src/ui/ai_sidebar/`，宿主窗口里的 view）：每条提问与回答的气泡下方
  有朗读按钮，点它朗读该条文字，正在读这条时按钮换成停止、再点一次停。回答先去掉
  Markdown 记号（代码块、表格与原始 HTML 跳过，链接与图片只读标签），提问按纯文本读；
  一条消息一个会话，块 id 以消息 id 为前缀，侧栏不做逐段高亮（按钮图标即状态）。

当前朗读段尽量滚到可视区；高亮只切换一个可逆的类（DjVu 面板用 `<mark>`）。朗读不写
数据库、不改正文：原文、笔记锚点、选区文本与 AI 引用都不受影响。

## 引擎：为什么先用 Windows 系统语音

`src/speech/` 是引擎边界（`SpeechEngine`：列出语音 + 把一段文字合成成 WAV 字节），
当前实现是 WinRT `SpeechSynthesizer`，播放用 `MediaPlayer`——两者都复用项目已有的
`windows` crate（只加 feature），**零新依赖、零模型、离线、首字延迟低于 100ms**。
本机已装的中文语音：Microsoft Huihui / Kangkang / Yaoyao。

为什么不上本地小模型或云端：

| 方案 | 代价 | 什么时候值得换 |
| --- | --- | --- |
| Windows 系统语音（现状） | 音质机械；音色取决于系统装了什么 | 默认选择 |
| 本地小模型（Piper 20–60MB / Kokoro-82M ≈300MB） | 需要 ONNX 运行时依赖（dll 20–50MB）+ 模型文件 + 首次加载 1–3 秒 | 更在意音质、能接受依赖与首次延迟 |
| 云端 TTS | 每次点击 0.3–2 秒网络往返 | 能接受联网与延迟、要最好的音质 |

引擎边界就是为这种替换准备的：换实现不需要动阅读窗口与页面脚本。

### WinRT 调用固定在一个工作线程上

`src/speech/engine.rs` 把所有 WinRT 调用投递到一个常驻的 MTA 工作线程（`with_winrt`）。
这不是洁癖，是实测踩到的两条坑：

1. `windows` crate 的工厂激活缓存把接口指针缓存在进程里，**跨公寓**使用会打出访问违例
   （0xC0000005，在 `SpeechSynthesizer::AllVoices()` 上随机复现；加锁不解决——问题不在
   并发，而在缓存对象被别的公寓的线程使用）；
2. `RoInitialize` 在已经是 STA 的线程上会以 `RPC_E_CHANGED_MODE` 失败，静默忽略就把
   WinRT 调用留在了没有正确公寓的线程上。

所以**不要**把 WinRT 调用搬回调用方线程，也不要在别的线程上新建 `SpeechSynthesizer`；
`src/speech/tests.rs::concurrent_voice_enumeration_never_crashes_the_process` 是这条约束
的护栏（去掉投递、改回直接调用，并行跑整套测试会随机崩进程）。

### 语速映射（2026-10-10 实测标定）

`SpeechRequest::rate` 是倍率（1.0 正常），映射到 WinRT `SpeakingRate` 是**恒等**，
`engine.rs` 只做范围钳制。实测曲线（Huihui 与 David 一致，说明由引擎决定、与音色无关）：

- `0.2..=5.0`：朗读时长与 rate 成反比（`1.0` 档的时长 ÷ rate），误差 <1%——界面
  0.75x–2.0x 档名副其实，0.5x 也是原生半速；
- 负值：被引擎忽略，输出与 0.0 逐字节一致，**不要用负值表达慢速**；
- 0.0：语音库自己的慢速基准（约 1.0 档的 1/5.7），不是“正常速度”；
- `>5.0`：增益递减，约 5.7 倍处饱和。`RATE_MAX = 10.0` 超出原生的部分需要重采样
  补齐，尚未实现；界面预设全部落在原生范围内。

`src/speech/tests.rs::speech_rate_presets_scale_duration_inversely` 是这段语义的护栏：
各档实际时长必须与 1.0 档成反比（15% 容差）。

## 三个窗口的分工

宿主侧的共享层是 `src/ui/read_aloud.rs`：会话状态机（`ReadAloudHost`）、进程级登记表
（`ReadAloudRegistry`）、段落容量校验与 `ReadAloudWindow` trait 的默认流程（读设置、
起会话、轮询、呈现、停止）。各窗口只说明两件事：**读什么**与**高亮怎么呈现**。

| 窗口 | 段落从哪来 | 高亮通道 |
| --- | --- | --- |
| EPUB 阅读窗口 | 章节页面按显示模式收集（有译文层就读译文） | 页面脚本 `ngyReadAloud` |
| PDF 阅读窗口 | PDF.js 文字层，已绘制页面按行距合并成段 | 页面脚本 `ngyPdfReadAloud` |
| 页面图片窗口 | 宿主按当前页文字切段（与面板共用 `page_text_paragraphs`） | 面板 HTML 里的 `<mark>` |
| AI 问答侧栏 | 整条消息（回答经 `ai_sidebar/markdown.rs` 清洗，按段落成块） | 无（按钮图标即状态） |

## 术语

- **朗读会话**：一次「从某段开始读到底」的过程。进程内**同时只允许一个**——系统语音与
  音频输出各只有一份。
- **音色**：一条系统语音（`SpeechVoice`），按 ID 持久化；空 ID 表示系统默认语音。
- **语速**：倍率，1.0 为正常，映射到引擎是恒等（见「语速映射」）。合法范围是
  `SpeechRequest::RATE_MIN..RATE_MAX`；读取设置时钳制，手改坏的行不会让阅读窗口打不开。
- **预取**：会话在播放当前段时合成下一段（最多提前两段），段与段之间因此几乎无间隙。

## 不可破坏的约束

- **EPUB 读什么**：跟随译文显示方式。页面按「该段有译文层就用译文层的文字，否则用正文
  文字」收集段落，所以「译文」与「双语」模式读译文、「原文」模式读原文；某段译文还没生成
  时读它当前显示的文字（所见即所读），不等待、不排队、不提示。
- **EPUB 不读什么**：代码块与表格跳过（读出来没有意义），标题、段落、列表、引用正常读。
  脚注等其它结构暂未特殊处理：作为普通段落出现的脚注文字会被读出。
- **EPUB 触发方式不用单击段落**：正文的 `pointerup` 已被笔记占用（拖选后的选区工具栏与
  点击划线弹卡片），单击朗读会和它们打架；段落上的小喇叭是内联 SVG、没有文本节点，因此
  不进入块的 `textContent`，也不会被选区复制。
- **EPUB 译文层不是朗读对象**：译文层会给每个块复制一份与源同名的文本元素（`<p>` 的译文
  还是 `<p>`），候选块必须排除 `[data-ngy-translation]` 子树，否则同一段会被读两遍、段落
  索引也会整体后移。
- **PDF 段落是推测的**：文字层是绝对定位的行片段，没有段落语义。收集时按行距（默认行高
  的 0.6 倍）合并相邻行，超过 480 字符的段按句末标点切开；行序在几何上跳回去（多栏或定位
  包装）就另起一段。改动这些阈值要重跑 DOM 探针。
- **PDF 只读已绘制的页面**：连续滚动按需渲染，未绘制的页没有文字层。读到已绘制范围的末尾
  就停；要继续读，滚动带出后面的页面后再点一次朗读（与笔记「只有已绘制的页面会显示标记」
  是同一条限制）。
- **PDF 不提供段落悬停按钮**：文字层是绝对定位的片段，插入按钮会打乱排版并抢走单击；
  PDF 窗口只用工具栏入口。
- **DjVu 段落索引与面板显示同一份切分**：`page_text_paragraphs` 同时喂给面板 HTML 与朗读
  块，高亮按索引对齐；两处切分不得分叉。
- **DjVu 只对隐藏文字层开放**：Office 逐页预览是图片页，没有文字层，工具栏不显示朗读按钮；
  Office 图书的结构化阅读在阅读窗口里，那里已经支持朗读。
- **单会话**：开始新的朗读前，`ReadAloudRegistry` 里登记的旧窗口先停；系统配置窗口的
  「试听」同样占用音频输出，会打断正在进行的朗读。
- **生命周期**：EPUB 切显示方式、切章与重新加载立即停止；页面图片窗口翻页与关闭时停止；
  PDF 连续滚动不停止（同一篇文档，没有换章语义），关闭窗口时随窗口释放收敛；AI 问答
  侧栏在宿主关闭、新建或切换会话时停止（消息列表会被整体替换，旧消息随之不存在）。
- **输入校验**：段落列表一律按不可信输入处理——最多 2000 段、单段 8 KiB、合计 512 KiB；
  EPUB 与 PDF 的页面请求还要校验起点 id 的长度。段落 id 只用于这一轮的对齐，不持久化。

## 设置

「系统配置」窗口的「朗读」段（音色、语速、试听），存全局 key
`speech.preferences.v1`，并列入 `AI_SETTINGS_KEYS` 的回滚清单。它是**应用级**设置：
不按书记忆，因此不需要任何删书清理。EPUB 与 PDF 阅读窗口工具栏的朗读按钮旁有「设置」
入口，直接打开这一段；音色与语速保存后立即对新的朗读生效。

## 验证

- `cargo test --lib speech`：真实调用系统语音，验证语音列表、WAV 产物、未知音色报错、
  语速钳制、倍率语义（各档时长与 1.0 档成反比）与播放到结束（会出声一次，一秒以内）。
- `cargo test --bin ngy-book-studio ai_sidebar`（ui 在 bin 目标）：侧栏操作条渲染出朗读
  按钮、Markdown 朗读清洗与消息块切分；点击「没有可朗读文字」的消息只报错、不启动会话
  （不触发真实合成）。
- `src/ui/read_aloud.rs` 的单元测试守住段落容量校验；`src/ui/page_image/tests/` 守住面板
  分段与 `<mark>` 高亮的索引一致。
- `src/ui/reader/read_aloud.test.cjs` 与 `src/ui/pdf_reader/read_aloud.test.cjs` 是可选 DOM
  门禁（Node + 已安装 Playwright，用法见 `environment-and-commands.md`）；本机没有
  Playwright 包时，可以用仓库里 headless Chromium 的 `--dump-dom` 跑探针页验证真实 DOM
  行为（EPUB：候选块、跳过代码/表格、译文跟随、高亮与清除；PDF：行合并成段、句末切分、
  高亮覆盖整段、滚动后起点跟随视口）。
- 人工冒烟：三个中文音色各听一段、暂停与继续、点另一段切换、切章/翻页/切显示方式是否立即
  停止、双语与原文模式读的文字是否正确、PDF 滚动后朗读起点是否正确、DjVu 面板高亮是否跟随、
  朗读中滚动是否跟随、朗读时笔记与选区是否照常。
